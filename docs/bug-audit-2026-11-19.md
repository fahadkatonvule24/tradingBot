# TradingBot bug audit — 19 November 2026

The current working tree contains **16 confirmed defects or behavior mismatches: four P1 and twelve P2**. P1 means a high-priority execution or account-risk defect; P2 means a reproducible correctness or behavior-alignment defect. These are findings, not applied fixes.

The review covered execution, position management, the MT5 adapter, configuration, strategy generation, portfolio simulation, dashboard operations, account sizing, notifications, and the generated plan. Existing uncommitted work was preserved. The working files changed during the audit, so the main reproductions, test suite, and dashboard checks were repeated against the later version. An earlier omission of the profit-only reverse-exit rule in the generated plan was corrected in that later version and is not counted below.

Verification:

- `python -m pytest`: **661 passed**, 55.68 seconds.
- `python -m ruff check src tests scripts`: **passed**.
- `python -m ruff format --check src tests scripts`: **96 files already formatted**.
- `node tests/dashboard_dom.cjs`: **81 checks passed** against the synthetic preview. The temporary server and worker were stopped afterward.
- Targeted reproductions used synthetic data, in-memory books, and the existing `FakeMT5`. They did not connect to a terminal, send real orders, or deliver notifications.

Passing tests do not cover the cases below. This is a bounded audit, not proof that every possible bug has been found. DOM checks exercise interactions; they do not verify rendered CSS alignment or canvas pixels. Broker execution was not tested on a live or demo terminal.

**F01 — P1: A demo-to-real account switch bypasses the startup permission check**

Location: [cli.py](../src/tradebot/cli.py), lines 289–298; [live.py](../src/tradebot/live.py), `LiveRunner._process`.

`cmd_run` evaluates `trading_gate` once and stores the result in `Engine.execute`. The loop does not re-evaluate that gate before subsequent engine actions. If the terminal changes from a demo account to a real account, the previously authorized engine continues sending orders with `allow_real_account=False`.

Reproduction: pass the gate on `FakeMT5` in demo mode, construct the engine, set `trade_mode=2`, and process a fresh buy signal. Rechecking the gate returned `execute=False` with the real-money refusal, but the runner still sent **one order**.

Correction: verify the current account and execution permission before every execution cycle/action; invalidate account-dependent state on account changes. The dashboard's per-order gate already illustrates the required recheck.

**F02 — P1: A timed-out order remains executable**

Location: [ui/monitor.py](../src/tradebot/ui/monitor.py), lines 490–499 and 519–539.

`submit` returns an error when its wait expires but leaves the order in `_orders`. The worker subsequently executes it without checking cancellation or a deadline. A user can receive a failure, retry, and then have both requests execute once the worker catches up.

Reproduction: call `submit(..., timeout=.001)` before starting the worker. It returns `ok=False`, `timed out waiting for the MT5 thread`. Starting the worker afterward sends **one successful fake BUY** for that request.

Correction: track request state and deadlines. Cancel requests that have not started, and report a pending/unknown outcome for an in-flight order rather than presenting it as a definite failure. Add an idempotency identifier for retries.

**F03 — P1: Automatic partial profit can close a losing position using a pre-entry bar**

Location: [protect.py](../src/tradebot/protect.py), lines 180–191 and 275–276; [ui/monitor.py](../src/tradebot/ui/monitor.py), lines 595–604.

The protection interface retains only a bar's close and ATR, losing its timestamp. `partial_close` compares that close with the position's entry without requiring the bar to have closed after the entry or checking current executable profit. A newly opened trade can therefore qualify based on prices it never experienced while open.

Reproduction: a 0.10-lot buy entered at 1.1002 with initial stop 1.0992; the preceding bar closed at 1.1022, while the current bid is 1.1000. The keeper sends a **0.05-lot close**, reporting **+2R**, although the position is currently **−0.2R**. The old bar predates the trade.

Correction: carry the bar close time through protection, require it to follow the entry for bar-triggered profit actions, and validate the current exit price. Apply the same timestamp discipline to trailing decisions.

**F04 — P1: Netting reversal deals are dropped from account risk history**

Location: [broker/mt5.py](../src/tradebot/broker/mt5.py), lines 371–380.

The adapter admits `DEAL_ENTRY_IN`, `DEAL_ENTRY_OUT`, and close-by deals but discards `DEAL_ENTRY_INOUT`. An INOUT deal reverses a position and can realize a loss; this is part of the [official deal-entry contract](https://www.mql5.com/en/docs/constants/tradingconstants/dealproperties). No netting-account restriction prevents this path.

Reproduction: provide a buy/sell deal with `entry=2` and `profit=-1000`. `broker.deals(..., magic=None)` returns **an empty list**. That realized loss is absent from the history used by daily/weekly loss limits and review calculations.

Correction: model both the closing and opening portions of reversal deals, preserving realized P/L, fees, and volume accounting. Alternatively, explicitly reject unsupported netting accounts before offering trading/risk functionality.

**F05 — P2: A stale startup tick can lock in the wrong UTC offset**

Location: [broker/mt5.py](../src/tradebot/broker/mt5.py), lines 149–153 and 166–178.

Clock detection treats the difference between a tick's timestamp and current time as the server offset whenever its absolute value is at most fourteen hours. Tick age is indistinguishable from offset in this calculation, and the chosen rule is cached. A stale visible instrument can be selected before a usable instrument.

Reproduction: a server at UTC+2 with a twelve-hour-old tick is detected as **UTC−10**. The stale tick then passes `Tick.problem`. When fresh ticks resume, they are rejected as more than sixty seconds in the future; the cached rule does not correct itself.

Correction: validate clock candidates against independent timing/history evidence and multiple instruments, defer uncertain detection, and retry after fresh data arrives. An explicit `server_utc_offset_hours` is a workaround, not an automatic correction.

**F06 — P2: Partial fills are reported as rejected orders**

Location: [broker/mt5.py](../src/tradebot/broker/mt5.py), lines 494–499; [ui/monitor.py](../src/tradebot/ui/monitor.py), `_place`.

Only return code 10009 is considered successful. MT5 code 10010 indicates partial completion, according to the [official trade return codes](https://www.mql5.com/en/docs/constants/errorswarnings/enum_trade_return_codes). Executed exposure can therefore be labelled `REJECTED`, and the returned fill volume is discarded.

Reproduction: a fake result with `retcode=10010`, ticket 777, and filled volume 0.05 produces `OrderResult(ok=False, ..., message='partially filled')`.

Correction: represent partial completion explicitly, preserve actual filled volume, and reconcile the resulting position/deals before reporting the outcome or handling a retry.

**F07 — P2: Portfolio simulation evaluates entries before advancing all peer symbols**

Location: [backtest.py](../src/tradebot/backtest.py), lines 111–126.

The loop advances one symbol with `sim.start_bar` and immediately evaluates its engine decision. Symbols later in alphabetical order still carry prices and positions from the previous timestamp. An earlier symbol's entry can be evaluated before a later symbol's intrabar stop has freed capacity or realized a loss.

Reproduction: with one total position allowed, B opens at 10:15 and stops during the bar ending 10:30; A signals at 10:30. The result is only B's stopped trade and `{'positions': 1}`. Rename A to Z without changing data: B stops first and **Z's entry succeeds**, producing two trades.

Correction: process intrabar exits and current marks for every symbol in a timestamp group before evaluating any close-time engine decisions. Retain a documented ordering only for genuinely competing simultaneous new entries.

**F08 — P2: Historical sizing uses a static tick value while P/L uses dynamic conversion**

Location: [broker/sim.py](../src/tradebot/broker/sim.py), lines 119–120 and 200–218; [engine.py](../src/tradebot/engine.py), lines 495–498 and 546 onward.

`SimBroker.symbol` returns a fixed specification and the simulator provides no `calc_profit`. Engine sizing falls back to that snapshot tick value, while `_pnl` uses the historical exit price to convert USD-base pairs. The same intended risk consequently produces different lot sizes in simulation and live pricing.

Reproduction: USDJPY at 100, ATR 1, a 1.5-price-unit stop, $10,000 equity, and 0.25% risk, with zero spread/commission. The engine plans **0.02 lots / $20.10 risk** against a $25 budget. The simulator records **$30 initial risk** and **$30.45685 loss** at stop 98.5.

Correction: implement simulated profit calculation consistent with `_pnl`, and use consistent historical conversion for sizing and portfolio-risk calculations.

**F09 — P2: D1 automatic trend selection blocks every entry**

Location: [strategy.py](../src/tradebot/strategy.py), lines 260 and 288–289; [config.py](../src/tradebot/config.py), automatic trend ladder.

The automatic higher-timeframe ladder for D1 is empty. Signal calculation assigns `trend=0` but still applies the requirement for a positive or negative trend whenever the trend filter is enabled. This valid configuration silently blocks all setups needing that filter.

Reproduction: 1,000 synthetic daily bars with the other filters disabled produce **16 raw triggers and zero entries**. Disabling only the trend filter produces **16 entries**.

Correction: treat an intentionally empty automatic ladder as no higher-timeframe filter, or reject the configuration with an explicit explanation.

**F10 — P2: A validated trend timeframe string crashes feature generation**

Location: [config.py](../src/tradebot/config.py), lines 185–190 and 550 onward.

`trend_timeframes: "H4"` passes validation, but `trend_ladder` converts it using `tuple(value)`, producing `('H', '4')`. Fetching features then looks up an unsupported timeframe.

Reproduction: load that JSON setting successfully, then call `latest_features`; it raises **`KeyError: 'H'`**. Live symbol processing cannot produce advice/signals for this accepted configuration.

Correction: accept only `"auto"` or a sequence of complete timeframe names, or normalize a single supported string to a one-element tuple.

**F11 — P2: Calculator maximum lots contradict actual margin**

Location: [calculator.py](../src/tradebot/calculator.py), lines 141–155.

The trade's displayed margin can use the terminal's exact calculation, while maximum lots under the margin cap and free margin always use theoretical notional/leverage. Instrument-specific leverage or fixed margin therefore produces contradictory advice.

Reproduction: equity $10,000, 30% margin cap, broker margin $10,000 per lot, and a 0.5-lot request. The calculator correctly shows **$5,000 margin**, but advises **2.72 lots** under the cap instead of **0.30**, and **9.08 lots** against free margin instead of **1.00**.

Correction: compute the caps with the same broker margin model used for the displayed trade, including tiering where applicable. Label hypothetical leverage calculations separately.

**F12 — P2: Other-account sizes ignore changing floating equity**

Location: [ui/desk.py](../src/tradebot/ui/desk.py), lines 347–366 and `size_lines`.

Other-account plans are cached by closed-bar timestamp, book version, and selected account. Those values do not change when quotes move and an open position changes the other account's equity. The dashboard and alert text can keep presenting stale sizes and percentages for the whole bar.

Reproduction: at 1% risk, an account with $3,000 equity yields **0.20 lots / $30 risk**. A price move reduces its equity to $1,500 without a new bar or book edit. The cached result still claims $3,000 equity and 1% risk; recomputation gives **0.10 lots / $15 risk**.

Correction: refresh these sizes when valuation inputs change, or include current equity, quotes, relevant positions, and parameters in cache validity.

**F13 — P2: Selecting the global default setup cannot override a symbol's own setup**

Location: [ui/static/index.html](../src/tradebot/ui/static/index.html), lines 1181–1182 and 1544; [ui/monitor.py](../src/tradebot/ui/monitor.py), lines 414–420.

The supplied configuration uses global EMA cross and breakout overrides for GBPUSD/XAUUSD. Their alternate EMA tile says it will show that setup in detail, but `switchTo` returns early because the global state already says `ema_cross`. The server also leaves overrides unchanged when asked for the current global setup; returning to that setup from another restores the configured overrides.

Reproduction: a symbol with a breakout override remains **breakout** after `_apply_strategy('ema_cross')` responds **“Now watching the ema cross setup.”**

Correction: distinguish restoring configured per-symbol setups from explicitly selecting one setup. Determine whether the selected symbol actually has the requested setup before treating the action as a no-op.

**F14 — P2: Telegram can replay old mutations after an initial network failure**

Location: [notify.py](../src/tradebot/notify.py), lines 148–165.

When the initial backlog-skip request fails, `_skip_backlog` returns zero. The listener then resumes ordinary handling from offset zero, allowing older commands to run despite the documented promise to skip them. These commands do not place broker orders, but can reset equity, duplicate logged trades, or amend/close book records used by later risk calculations.

Reproduction: make the first fake update request raise `TelegramError`, then return an old `/equity Main 10000` message. The listener requests offsets **−1 then 0** and executes that old command.

Correction: retry establishing the startup boundary before enabling command handling; consider persisted processed IDs and message-age validation for mutating commands.

**F15 — P2: The generated trading plan can name the wrong strategy**

Location: [plan.py](../src/tradebot/plan.py), lines 171–173.

When `setup_groups()` returns one group, the plan uses the global strategy rather than that group's effective strategy. If the selected symbols all override the global strategy, the described entry rules disagree with the engine.

Reproduction: global EMA cross with only EURUSD selected and an EURUSD breakout override. Effective groups are `[('breakout', ['EURUSD'])]`, while the plan says **“Setup (EMA cross): EMA 10 closes across EMA 50…”**. A CLI subset containing only an overridden symbol can also expose this.

Correction: derive even a single-group plan from that group's resolved symbol parameters. Keep genuinely differing per-symbol rules visible.

**F16 — P2: The STOP-file pause does not cover new manual dashboard actions**

Location: [ui/monitor.py](../src/tradebot/ui/monitor.py), lines 1400–1411 and 1544–1553; `duplicate`/`_order_gate`. The documented promise is in [README.md](../README.md), Safety model, and the generated plan's manual off-switch rule.

`get_in_rule` excludes only data failures, so a `kill switch:` rejection is treated as an overridable trading limit. `Duplicate` also checks execution permissions but not the STOP file. This conflicts with the stated behavior that creating STOP pauses new entries; neither manual exception is documented in that rule.

Reproduction: use a temporary STOP file and a fresh fake buy signal. The ordinary manual order is refused with **“blocked by a risk rule: kill switch…”**. The same request with Get in enabled succeeds and sends **one fake order**, despite that file still existing.

Correction: enforce the operational kill switch in the common order gate before manual override/duplicate paths. If manual exceptions are an intentional product requirement, define and display that exception consistently instead of describing STOP as an entry off switch.

**Other check result**

The repository-wide `ruff check .` / `ruff format --check .` command documented in README also reports a missing final newline and formatting differences in `wordlist_generator/crunchmimic.py`. The scoped CI commands for `src`, `tests`, and `scripts` pass. This unrelated formatting issue is not included in the sixteen functional findings.

**Recommended correction order**

Address F01–F04 first, then broker clock/fill handling and the STOP-file contract. Next correct portfolio simulation and sizing, followed by dashboard cache/setup behavior, configuration validation, Telegram startup handling, and plan generation. Each fix should include the corresponding adverse scenario as a regression check; the existing passing suite does not establish these behaviors.

**Resolution (19 November 2026, same day)**

All sixteen findings are fixed in the working tree. Each one's adverse scenario is now a test in
`tests/test_audit_2026_11_19.py`. Some fixes chose between the options above:

- **F02.** An order still queued at the timeout is cancelled. One already being sent is reported as pending (HTTP 202, "not confirmed yet"). The page sends one request id per confirmation, and a repeat of it is answered with the first outcome.
- **F04.** A reversal deal is returned as an "out" with the realised result plus an "in" for the volume left. The out volume is the position's open volume when its opening deal is in the queried range.
- **F05.** The offset comes from the freshest quote of all visible symbols. A clock measured from a quote that is not live (not within two minutes of a quarter-hour offset) is measured again every minute. A quote stamped more than a minute in the future triggers a new measurement. A server change on an account switch triggers one as well. An explicit `server_utc_offset_hours` is never re-measured.
- **F09.** The configuration is refused at start, with the reason, rather than silently trading without the filter.
- **F13.** A setup button shows that setup on every instrument. A new **As configured** button restores the per-symbol setups from the config.
- **F16.** The STOP file is checked in the common order gate. Get in also refuses a `kill switch` hold-up, and Duplicate shows as unavailable while the file exists.

On the other check: README now documents the scoped lint command that CI runs (`ruff check src tests scripts`). `wordlist_generator/crunchmimic.py` was left untouched.

Verification after the fixes: 685 tests passed, `ruff check` and `ruff format --check` pass on `src tests scripts`, and mypy reports no issues in 42 source files. 84 dashboard DOM checks passed against the synthetic preview. Broker behaviour was still tested only with the fake terminal, not on a live or demo terminal.
